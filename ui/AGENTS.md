# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

This is an adult DUPLO controller. 2026-10-05 simplification (user request: the app must be easy to understand and use, without extra complexity): one centered column — a "Connect your train" step card when disconnected, then Drive, Headlight & Sounds, and collapsible optional panels (DJI remote, Purple brick sound, Power) with a one-line subtitle and status chip. Debug is open by default as a side column (below on narrow screens) and can be hidden with the top-bar **Debug** button; connection details live inside it. Keep the dark palette and red Stop from `reference/selected-design.png`, but that image no longer defines the layout. Color means state: Backward/Forward are neutral and the direction the train is moving lights up blue; panel chips show live state (e.g. "Clip ready", "Off in 4:59"), not disclaimers. DJI stick controls appear only once the remote is connected. No tabs or separate screens. Keep copy short; put long explanations in `../docs/app-behavior.md`, not on screen. Preserve the local Bluetooth backend and existing DJI listener when changing the UI.

The user also requested forward/backward, colors, sound, shutdown timing, and a recording for the purple brick. Purple brick sound and Power are inline collapsible panels (collapsed by default; the DJI panel always opens by default). Distinguish audio played on the Mac from uploads to the train speaker, and the app's idle timer from LEGO's native snooze setting. Never present an unverified proprietary command as supported.

Sound actions must be direct buttons, not a dropdown with a separate Play action. The user expects purple recordings to play from the train itself; local/Mac playback is a partial fallback, not completion of that requirement. Preserve existing recorded clips while investigating native transfer.

DJI train driving uses Wi-Fi. Forward/reverse must remain available from both computer buttons/keyboard and the DJI left stick's vertical axis. All other actions (lights, sounds, power and settings) are computer-only; do not map DJI buttons to train actions. Computer driving takes priority until the left stick centers. Computer Stop requires a centered stick before DJI motion can resume. Keep computer driving available if the Wi-Fi input drops.

Left-stick driving uses one **Drive with left stick** switch in the DJI remote panel (it replaced the separate Driving controls dropdown and Enable/Disable button), with a live vertical position meter and motor-power reading. Invert and dead zone apply immediately (no Apply button). Motor power must increase proportionally with distance from center after the dead zone, up to the computer's speed setting. Readouts and drive commands must share the same backend mapping. Do not use horizontal stick displacement, the right stick or DJI buttons to set direction or power.

Enable the left stick by default. Automatically activate it when the train, fresh DJI input and an active control window are ready, requiring a new centered sample before movement. The user confirmed the previous direction was reversed: use inversion by default for this RM330 so up drives forward and down drives backward. Remember explicit enable/disable and inversion choices across app restarts. Leaving the control window stops movement; returning can resume the enabled preference after centering. A background window must not suspend another window's active controls.

The DJI remote panel has a secondary **Search and connect** button beside **Connect** in the IP-address row (2026-10-07 user request and layout correction). Keep the two buttons grouped together when the row wraps on narrow screens. It discovers the remote on the Mac's current Wi-Fi, fills and remembers its IP, and connects automatically. Keep manual IP entry as a fallback, show searching and clear failure feedback, and allow cancellation. Automatic selection requires exactly one verified DJI stick-input stream.

Automatic connection (2026-10-08 user request): the start card offers **Connect both** (primary), **Train only** and **Remote only**. When the remote is already connected or being tried, or in Demo, it offers only **Connect train**. The top bar shows one status pill per device (Train, DJI remote): live state, battery or IP, and one small action. That action is **Stop** while tries run, **Reconnect**/**Connect** after a failure, drop or stop, and **Disconnect** for a connected train. **Stop both** appears when both are being tried. Each device is tried several times, and each can be stopped on its own. Don't show errors between tries in the banner; show the reason after the last failed try. Don't reconnect automatically after a device drops.

The DJI remote and Debug panels must both start open on every page load (2026-10-07 user request), including when no remote IP is saved. They can be closed during the current visit; an old saved Debug preference must not override these defaults.
